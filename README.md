# 핵심 시스템 및 기능

## 게임 시스템

### 1. 카드 기반 덱빌딩 체스 시스템
- **행동권 부여 시스템** : 카드를 소모하여 특정 기물에 행동권(Action Token)을 부여하는 독창적인 체스 룰 구현
- **전술 카드 시스템** : 드로우, 코스트, 특수 행동 및 효과 등을 가진 전술 카드로 다양한 컨셉 및 전략적 플레이
- **덱빌딩 시스템** : 매 전투 승리 시 카드를 획득하고 덱의 카드 제거 가능, 플레이어가 원하는 덱을 통한 다양한 전략의 체스 플레이
 
### 2. 자체 설계 휴리스틱 체스 AI 
- **가중치 기반 점수 평가**: 기물 가치, 위치 이점, 위협 가산점, 위험 감점 등 알고리즘을 바탕으로 그리드 별 점수 평가를 통해 행동 결정 
- **실시간 재평가 반복 처리**: 매 행동마다 체스판 캐시를 동적으로 재탐색하여 변경된 경로와 위협에 즉시 반응하도록 연산

### 3. 상태 머신 및 입력 차단 (FSM)
- **상태 머신 제어**: 각 행동, 페이즈 별 상태 제어 (ex: 드로우, Pause, 상대방 턴, 보상 페이즈)
- **입력 충돌 방지**: 카드 드로우/사용 애니메이션 및 덱 조회 팝업 등 유저 현재 상태 외부로의 입력을 차단하여 입력 충돌 및 레이캐스트 투과 방지

### 4. 태그 기반 카드 유효성 관리
- **동적 소멸 시스템**: 더 이상 체스판에 존재하지 않는 기물의 태그를 감지하여, 기물이 없어 사용할 수 없는 해당 기물 태그의 카드가 드로우될 때 자동으로 소멸하는 동적 규칙 적용

### 5. 3D/2D 혼합 렌더링 
- **서브 뷰포트 통합**: 서브 뷰포트를 활용해 3D 체스 보드와 2D 카드 UI/UX 레이어를 하나의 화면으로 통합

## 자체 설계 체스 AI 

### **점수 평가 기반의 휴리스틱 체스 AI**

- 각 기물이 수행 가능한 행동을 탐색하고, 행동별 점수를 계산
- 가장 높은 평가 점수를 획득한 행동을 선택하여 수행

### 점수 연산 기준

- **기물 점수** : 각 기물별로 기존 체스의 기물 가치를 반영해 점수 할당
- **공격** : 직접 제거할 수 있는 기물이 있는 경우, 공격 할 그리드에 있는 상대방 기물 만큼의 가치 합산
- **통제력** : 각 그리드에 가치를 부여, 중앙에 가까울수록, 목표 기물에 가까울수록 높은 가치 부여, 해당 그리드에서 기물이 개입 가능한 그리드들의 가치만큼 합산
- **위협** : 해당 그리드로 이동했을 때 공격 가능한 상대방 기물이 존재 할 경우, 해당 기물 가치의 일정 비율만큼 그리드의 점수에 합산
- **보호** : 해당 그리드로 이동했을 때 이동 가능한 범위 내에 아군 기물이 있는 경우, 해당 기물 가치의 일정 비율만큼 점수에 합산
- **회피** : 그리드 점수 산출 시 상대방의 이동가능 영역 안이라면 해당 기물 가치만큼 해당 그리드의 점수 차감
- **위협 차단** : 아군 상위 기물을 위협하는 상대 기물을 제거할 경우 추가 점수 

### AI 추가 예정 요소 

- 난이도 : 점수 평가 기반 최선의 선택만을 내리는 것이 아닌 차선 또는 그 후순위의 행동을 선택할 확률을 설정함으로서 난이도 조정
- 공격성 : 과감하게 희생을 감수하고 공격 할 수 있도록 별도의 변수 부여

### 캐싱

- 매 행동 후 체스판 상황 및 점수 평가를 캐싱하여 점수 평가 시 재사용, 게임 내 발생한 변화 요소만 연산 로직에 근거해 연산
- 처음부터 연산하는 것이 아닌 이전 기록에서 영향을 받는 부분만 추가로 연산하여 행동별 점수 평가 과정에서의 불필요한 부하 방지

## 아키텍쳐 및 디자인 패턴

* **컴포넌트 중심 아키텍처**
  * 개별 기능(룰, 카드 효과 등)을 독립된 노드 및 스크립트로 분리하여 코드 간 결합도를 최소화 함으로서 연쇄적 오류 방지 및 유지보수의 용이성과 확장성 확보

* **유한 상태 머신 (FSM)**
  * 플레이어 조작, 턴 진행, 시스템 반응 등을 상태 단위로 통제하여 입력 충돌 및 예외 동작 차단

* **데이터 주도 설계**
  * 데이터와 로직 스크립트를 분리하여 데이터 확장 및 밸런싱 편의성 확보

* **시그널 중심 전역 통신**
  * "Call Down, Signal Up" 원칙을 준수하여 노드 간의 직접적인 참조를 최소화하고, 이벤트 기반으로 상태 변화 전달
