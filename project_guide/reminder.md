# 📌 개발 리마인더 & 아키텍처 규칙 (Reminder)

본 문서는 프로젝트가 복잡해지더라도 일관된 구조를 유지하기 위해, 지금까지 정의된 **상태(FSM), 핵심 키워드(함수), 그리고 데이터 설계 규칙**을 기록하는 곳입니다.

---

## 1. 전역 상태 머신 (FSM: Finite State Machine)
모든 주요 동작은 입력 충돌(버그)을 방지하기 위해 반드시 상태(State)에 따라 철저히 통제됩니다.

### 🃏 CardManager (카드 제어자) 상태
*   `State.IDLE` : 기본 대기 상태. 카드를 클릭하거나 드래그할 수 있습니다.
*   `State.DRAWING` : 덱에서 카드를 뽑아 손패로 날아오는 연출이 진행 중인 상태. (충돌 방지를 위해 플레이어 조작 차단)
*   `State.PLAYING` : 카드를 필드에 내어 효과가 발동 중인 상태.
*   `State.VIEWING` : 남은 덱이나 버린 덱을 클릭하여 팝업 UI로 카드들을 확인하고 있는 상태. (뒤쪽 3D 상호작용 차단)
    *   **입력 차단**: 이 상태에서는 마우스 조작(드래그, 카드 사용 등)이 완전히 무시됩니다.
*   `State.PLAYING` (향후 추가 예정): 카드를 사용해서 이펙트가 터지고 적에게 데미지가 들어가는 중인 상태.

---

## 2. 핵심 모듈 키워드 (Core Methods)
반복되는 복잡한 연출이나 로직은 반드시 아래와 같이 모듈화(함수화)된 키워드로만 호출합니다.

*   `execute_drawing(amount: int)` 
    *   **역할**: 덱에서 `amount` 장수만큼 카드를 뽑고, 딜레이와 3D 애니메이션을 포함한 모든 시각/논리적 절차를 총괄합니다.
    *   **특징**: 호출 시 자동으로 `State.DRAWING`으로 진입하며, 애니메이션이 끝난 후 스스로 `State.IDLE`로 복귀합니다.
    *   **사용처**: 게임 시작, "n장 드로우" 효과를 가진 카드 사용 시 등.

*   `execute_card_view(pile_cards: Array[String], title: String)`
    *   **역할**: 주어진 카드 ID 배열을 읽어 화면에 2D 그리드 UI로 띄워주는 카드 확인 전용 팝업 시스템입니다.
    *   **특징**: 호출 시 화면 배경이 어두워지고 `State.VIEWING` 상태로 진입하여 뒤쪽 3D 상호작용을 차단합니다. 배경이나 닫기를 누르면 스스로 소멸합니다.
    *   **사용처**: 좌측 하단 남은 덱 클릭 시, 우측 하단 버린 덱 더미 클릭 시.

## 3. 데이터 및 덱 시스템 구조 (Data-Driven)
*   모든 카드는 이름(String)이 아닌 **`id` (고유 문자열 ID, 예: "searing_blade")**를 기준으로 통신합니다.
*   **특수 코스트 (X 코스트)**: 코스트가 가변적인 카드는 숫자 대신 `COST_X (-1)` 상수를 코스트로 가집니다. 동시에 `tags` 배열에 `"X_Cost"` 태그를 반드시 포함하여, 카드 사용 시 마나 시스템이 이 태그를 인식하고 남은 마나를 모두 소모하도록 데이터 주도적으로 설계합니다.
*   `DeckComponent`는 원본 데이터를 훼손하지 않기 위해 `draw_pile`, `discard_pile`, `exhaust_pile` 배열을 자체적으로 복사하여 셔플/관리합니다.
*   **플레이어 진영(Player Team) 제어**: `BoardManager.gd`의 `@export var player_team: PieceData.Team` 변수로 플레이어가 플레이할 진영(WHITE/BLACK)을 결정합니다. 카드 사용 시 얻는 행동 토큰 및 기물 조작(`BoardInput.gd`)은 오직 `is_player_piece()`를 통과한 플레이어 진영의 기물에만 적용되며, 적 AI(`AITestRunner.gd`) 역시 상대 진영 기물을 자동으로 식별하여 조작합니다.

## 4. AI 제어 시스템 & 승리 판정 철학 (AITestRunner)
*   **CHESSHIRE 승리 조건 철학**: 전통 체스와 달리 체크메이트(외통수) 상태여도 플레이어가 다음 턴에 해당 기물 카드를 뽑지 못하면 기물을 움직여 잡을 수 없습니다. 따라서 **체크메이트가 확정되었더라도 `Objective` (킹/보스 기물)가 물리적으로 포획되어 소멸할 때까지 전투가 지속**됩니다.
*   **AI 평가 하한선 (`highest_score = -INF`)**: 코너에 몰리거나 절망적인 체크메이트 위기 상황에서도 AI가 이동을 포기하거나 턴을 스킵하지 않고, 주어진 상태에서 가장 피해가 적거나 최선의 항전 이동을 수행하도록 evaluation 하한선을 음의 무한대(`-INF`)로 보장합니다.
*   **행동 횟수 변수**: `AITestRunner.gd` 내의 `@export var ai_actions_per_turn: int = 2` 변수를 통해 AI가 한 턴에 수행할 총 행동(이동) 횟수를 결정합니다.
*   **실시간 재평가(Re-evaluation) 로직**: AI는 처음 한 번만 연산하고 순위대로 움직이는 것이 아니라, **매 행동(루프)마다 갱신된 체스판 상태를 바탕으로 캐시를 다시 빌드(`_build_cache`)하고 1위 행동을 다시 연산**합니다. 
    *   따라서 폰이 이동하여 막혀있던 공간이 열리면, 두 번째 행동 연산 시 퀸이 그 빈 공간을 새로운 공격 경로로 인지하고 즉각적으로 튀어나오는 등 매우 유기적인 판단이 가능합니다.
*   **단독 테스트 지원**: 향후 배틀 씬 전체가 아닌 AI 모듈만 격리하여 테스트할 수 있도록, `AITestRunner.gd`의 `_ready()` 함수 내부에 수동 턴 넘기기 UI 코드가 주석 처리된 상태로 보존되어 있습니다. 필요 시 주석을 해제하여 사용할 수 있습니다.

## 5. 카드 에셋 명명 및 데이터 관리 규칙 (Card Asset Naming Rules)
카드 리소스 파일(`res://Asset/Cards/`) 및 데이터베이스(`CardData.gd`) 관리 시 파일명 접두사 규칙을 엄격히 준수합니다.

*   **`T_` 접두사**: **전술 (Tactic/Spell) 카드**
    *   예: `T_Crusade.png`, `T_Disband.png`, `T_Lance Charge.png`, `T_Sabotage.png` 등
    *   기능: 마나를 소모하여 특수 효과, 버프/디버프, 이동 룰 변경 등을 일으키는 전술 카드.
*   **`W_` 접두사**: **백색 아군 기물 (White Piece) 카드**
    *   예: `W_Pawn.png`, `W_Knight.png`, `W_Bishop.png`, `W_Rook.png`, `W_Queen.png`, `W_King.png`
    *   기능: 플레이어 진영의 기물에 행동 토큰을 부여하거나 이동시키는 카드.
*   **`B_` 접두사**: **흑색 적군 기물 (Black Piece) 카드**
    *   예: `B_Pawn.png`, `B_Knight.png`, `B_Bishop.png`, `B_Rook.png`, `B_Queen.png`, `B_King.png`
    *   기능: 적 AI 진영 기물 데이터 카드.
