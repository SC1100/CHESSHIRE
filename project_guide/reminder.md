# 📌 개발 리마인더 & 아키텍처 규칙 (Reminder)

본 문서는 프로젝트가 복잡해지더라도 일관된 구조를 유지하기 위해, 지금까지 정의된 **상태(FSM), 핵심 키워드(함수), 그리고 데이터 설계 규칙**을 기록하는 곳입니다.

---

## 1. 전역 상태 머신 (FSM: Finite State Machine)
모든 주요 동작은 입력 충돌(버그)을 방지하기 위해 반드시 상태(State)에 따라 철저히 통제됩니다.

### 🃏 CardManager (카드 제어자) 상태
*   `State.IDLE` : 기본 대기 상태. 카드를 클릭하거나 드래그할 수 있습니다.
*   `State.DRAWING` : 덱에서 카드를 뽑아 손패로 날아오는 연출이 진행 중인 상태. (충돌 방지를 위해 플레이어 조작 차단)
*   `State.PLAYING` : 카드를 필드에 내어 효과가 발동 중인 상태.
*   `State.VIEWING` : 남은 덱이나 버린 덱을 클릭하여 팝업 UI로 카드들을 확인하고 있는 상태. (뒤쪽 3D 상호작용 차단)
    *   **입력 차단**: 이 상태에서는 마우스 조작(드래그, 카드 사용 등)이 완전히 무시됩니다.
*   `State.PLAYING` (향후 추가 예정): 카드를 사용해서 이펙트가 터지고 적에게 데미지가 들어가는 중인 상태.

---

## 2. 핵심 모듈 키워드 (Core Methods)
반복되는 복잡한 연출이나 로직은 반드시 아래와 같이 모듈화(함수화)된 키워드로만 호출합니다.

*   `execute_drawing(amount: int)` 
    *   **역할**: 덱에서 `amount` 장수만큼 카드를 뽑고, 딜레이와 3D 애니메이션을 포함한 모든 시각/논리적 절차를 총괄합니다.
    *   **특징**: 호출 시 자동으로 `State.DRAWING`으로 진입하며, 애니메이션이 끝난 후 스스로 `State.IDLE`로 복귀합니다.
    *   **사용처**: 게임 시작, "n장 드로우" 효과를 가진 카드 사용 시 등.

*   `execute_card_view(pile_cards: Array[String], title: String)`
    *   **역할**: 주어진 카드 ID 배열을 읽어 화면에 2D 그리드 UI로 띄워주는 카드 확인 전용 팝업 시스템입니다.
    *   **특징**: 호출 시 화면 배경이 어두워지고 `State.VIEWING` 상태로 진입하여 뒤쪽 3D 상호작용을 차단합니다. 배경이나 닫기를 누르면 스스로 소멸합니다.
    *   **사용처**: 좌측 하단 남은 덱 클릭 시, 우측 하단 버린 덱 더미 클릭 시.

---

## 3. 데이터 및 덱 시스템 구조 (Data-Driven)
*   모든 카드는 이름(String)이 아닌 **`id` (고유 문자열 ID, 예: "searing_blade")**를 기준으로 통신합니다.
*   **특수 코스트 (X 코스트)**: 코스트가 가변적인 카드는 숫자 대신 `COST_X (-1)` 상수를 코스트로 가집니다. 동시에 `tags` 배열에 `"X_Cost"` 태그를 반드시 포함하여, 카드 사용 시 마나 시스템이 이 태그를 인식하고 남은 마나를 모두 소모하도록 데이터 주도적으로 설계합니다.
*   `DeckComponent`는 원본 데이터를 훼손하지 않기 위해 `draw_pile`, `discard_pile`, `exhaust_pile` 배열을 자체적으로 복사하여 셔플/관리합니다.
*   **통신 원칙**: 노드 간 통신은 트리 경로 하드코딩이 아닌 `signal`을 통해서만 이루어집니다. (예: `DeckComponent`의 `counts_changed` 시그널로 3D 덱 뭉치 UI 업데이트)
