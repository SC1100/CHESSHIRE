## TASKS — 개발 체크리스트

> 만들어가면서 구체화하는 방식. MVP(최소 플레이 가능 버전)를 향해 단계별로 진행.

---

### Phase 1: 프로젝트 기반 세팅
- [ ] 폴더 구조 생성 (`scenes/`, `scripts/`, `resources/data/`, `scenes/components/` 등)
- [ ] Global.gd (Autoload Singleton) 생성 — 게임 상태, 턴 페이즈 enum 정의
- [ ] 전투 씬(BattleScene) 루트 노드 생성

---

### Phase 2: 보드 시스템
- [ ] 보드 데이터 구조 설계 (8×8 2D 배열, 타일 상태 관리)
- [ ] BoardManager 구현 — 보드 상태 읽기/쓰기, 좌표 변환
- [ ] 보드 시각화 — 타일 노드 생성 및 렌더링 (체스판 흑백 패턴)
- [ ] 타일 클릭/선택 입력 처리

---

### Phase 3: 기물(Piece) 시스템
- [ ] PieceData 리소스 설계 (.tres) — 기물 종류, 이동 규칙 정의
- [ ] Piece 씬 생성 — 기물 노드 (시각 표현 + 데이터 참조)
- [ ] 기물 초기 배치 로직 (표준 체스 배치 또는 커스텀)
- [ ] 기물 이동 규칙 로직 — 각 기물별 유효 이동 위치 계산
- [ ] 기물 선택 → 이동 가능 타일 하이라이트 표시
- [ ] 기물 이동 실행 및 보드 상태 갱신
- [ ] 기물 잡기(Capture) 처리

---

### Phase 4: 턴 시스템
- [ ] TurnManager 구현 — 턴 페이즈 FSM (PlayerTurn / AITurn / Mulligan 등)
- [ ] 턴 전환 로직 (플레이어 턴 종료 → AI 턴 → 플레이어 턴 시작)
- [ ] 턴 시작 시 이벤트 훅 (드로우 트리거 등)
- [ ] "턴 넘기기" UI 버튼

---

### Phase 5: 카드 데이터 & 덱 구조
- [ ] CardData 리소스 설계 (.tres) — 카드 이름, 코스트, 타입, 효과 ID, 키워드 등
- [ ] 기본 카드 데이터 N종 생성 (이동 카드 위주: 폰 전진, 나이트 이동 등)
- [ ] 덱/손패/버린카드 데이터 구조 (Array 기반 카드 풀 관리)
- [ ] CardManager 구현 — 덱 셔플, 드로우, 버리기, 덱 → 손패 이동

---

### Phase 6: 카드 UI & 핸드 관리
- [ ] 카드 UI 씬 생성 (카드 1장의 시각 표현)
- [ ] 핸드 UI — 손패 카드 나열, 선택, 사용 인터랙션
- [ ] 카드 사용 → 기물 이동 연결 (카드 선택 → 대상 기물 선택 → 이동)
- [ ] 사용한 카드 → 버린카드 더미 이동 시각 피드백

---

### Phase 7: 멀리건(Mulligan) 시스템
- [ ] 전투 시작 시 멀리건 UI — N장 공개 후 교환할 카드 선택
- [ ] 선택 카드 덱에 셔플 → 동일 매수 재드로우 → 손패 확정
- [ ] 멀리건 완료 후 Phase → PlayerTurn 전환

---

### Phase 8: AI 기본 행동

- [ ] AI 턴 시 자동 기물 이동 실행
- [ ] AI 턴 종료 → 플레이어 턴 전환 연결

---

### Phase 9: 승패 판정
- [ ] 승리/패배 조건 정의 및 체크 로직 (킹 잡힘 등 — 추후 구체화)
